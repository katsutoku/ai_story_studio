# AI Story Studio

小説・ノベルゲーム・アドベンチャーゲームのシナリオ制作を支援するWebアプリケーション（Flask版・雛形）。

仕様書「AI Story Studio 仕様概要書」に基づき、以下の情報管理機能を実装しています。

- プロジェクト（作品）管理
- キャラクター管理
- 世界設定管理
- 章管理（本文はMarkdownファイルとして保存）
- 伏線管理（pending / processing / completed / failed）
- **AIシナリオ生成（マルチプロバイダ対応）**：ChatGPT（OpenAI）/ Gemini（Google）/ Claude（Anthropic）/ Ollama（ローカル実行）から生成時に選択可能。作品情報・キャラクター・世界設定・過去章要約・未回収の伏線をプロンプトに含めて次章を自動生成
- **AIキャラクター生成**：作品情報（タイトル・ジャンル・あらすじ）と既存のキャラクター・世界設定をもとに、AIが新規キャラクター案をJSON形式で複数提案。プレビュー画面で内容を確認し、登録したいものだけ選んでDBに保存できる（未保存の下書き段階を挟むため、気に入らない案はそのまま破棄できる）
- **AI世界設定生成**：キャラクター生成と同じ設計で、世界観の案を複数提案・プレビュー・選択登録できる
- **AI伏線生成**：既存の章一覧を踏まえて配置章・回収章の候補も自動で対応付け。該当する章がない場合は未設定のまま登録され、後で手動編集できる
- **おまかせ生成モード（全体プロット一括生成）**：作品タイトル・ジャンル・あらすじと大まかな要望だけから、AIがキャラクター・世界設定・全章の設計図（本文はまだ書かない、タイトル・要約・目的のみ）・伏線をすべて連動させて一括提案。プレビュー画面で確認して選択登録した後は、章一覧から通常の章生成フローで1章ずつ本文を執筆する（本文生成時は、あらかじめ登録された「その章の設計図」と「今後の章の予定」が自動的にプロンプトへ反映されるため、行き当たりばったりにならず全体の伏線・展開と整合した本文が書かれる）

## セットアップ

```bash
python -m venv venv
source venv/bin/activate   # Windowsは venv\Scripts\activate
pip install -r requirements.txt

cp .env.example .env
# .env を編集し、SECRET_KEY と使用したいAIプロバイダのAPIキーを設定する

python run.py
```

起動後、ブラウザで `http://127.0.0.1:5000/` にアクセスしてください。

## 実装済みのエラーハンドリング

- 存在しないデータへのアクセス → 404エラー画面
- 章本文のMarkdownファイルが存在しない場合 → 空文字として編集画面を表示
- 必須項目未入力（タイトル・章番号・キャラクター名・プロジェクト名）→ 保存せず入力画面へ戻す
- 本文ファイル保存失敗時 → DB更新を中止しエラーメッセージを表示
- AI生成失敗時（認証エラー・通信エラー・レート制限など）→ 章の生成ステータスを`failed`に更新し、エラーメッセージを表示し、再生成可能な状態にする

## AIシナリオ生成機能の使い方

1. `.env` に、使用したいAIプロバイダのAPIキーを設定する
   - ChatGPT: `OPENAI_API_KEY`（https://platform.openai.com/api-keys ）
   - Gemini: `GEMINI_API_KEY`（https://aistudio.google.com/apikey ）
   - Claude: `ANTHROPIC_API_KEY`（https://console.anthropic.com/settings/keys ）
   - Ollama: APIキー不要。ローカルで `ollama serve` を起動し、`OLLAMA_BASE_URL`（デフォルト `http://localhost:11434`）と
     `OLLAMA_MODEL`（例: `llama3.1`）を指定する
2. `DEFAULT_AI_PROVIDER` で生成画面を開いたときに最初に選択されるプロバイダを指定できる（省略時は`gemini`）
3. 作品詳細画面、または章一覧画面の「AIで次章生成」ボタンから生成画面へ
4. 章番号（自動的に次の番号が入力される）・仮タイトル・**利用するAI（プルダウン）**・追加指示（任意）を入力して生成
5. 生成された本文は自動的にMarkdownファイルとして保存され、本文編集画面へ遷移する
6. 生成に失敗した場合は章一覧に「再生成」ボタンが表示され、別のAIプロバイダに切り替えて再試行することもできる

内部的には `app/ai_service.py` の `build_prompt()` が、作品情報・キャラクター・世界設定・
これまでの章の要約・未回収の伏線（`Foreshadowing.status == "pending"`）を
共通のプロンプトとして組み立て、選択されたプロバイダに応じて
`_generate_with_openai()` / `_generate_with_gemini()` / `_generate_with_claude()` / `_generate_with_ollama()`
のいずれかに振り分けている。どの章がどのAIで生成されたかは `Chapter.generation_provider` に記録される。

### 章構成の方針（常に適用される）

`build_prompt()` は、追加指示の有無にかかわらず常に次の方針をAIへ指示する。

- 各章は、それ単体で起承転結が完結する小さな事件・エピソードとして書く（「逆転裁判」のような話数完結型のイメージ）
- 同時に、その章の中に最終章で明かされる大きな謎につながる手がかりを、読者に今は気づかせない程度にさりげなく仕込む

この方針を章ごとに変えたい場合は、生成画面の「追加指示」欄で上書き・補足する。

### セリフのト書き表記（常に適用される）

ゲーム用シナリオスクリプトへの変換を見据え、本文中のセリフ行は必ず次の形式で書かれる。

```
【高橋健】「本当にここでいいのか？」
```

- 発言者名を行頭に`【】`で囲んで明記し、直後にセリフを`「」`で書く
- 発言者名は常に実名で表記する

「正体を隠したいキャラクターは？？？のように表記する」という案も検討したが、正体の開示タイミングは
ゲームのシナリオシステム側でフラグ管理するか、人が手を入れて調整する領域と考え、見送った。

### 場面情報の記載（常に適用される。本文の一番先頭）

背景画像の自動判別を見据え、本文の一番先頭には必ず次の2行が入る。

```
■背景:岸壁
■場面:深夜の岸壁
```

- **`■背景:`**：背景画像の判別に使う短い場所名（例：岸壁、教室、駅前）。時間帯や状況の修飾語は含めない。
  同じ物理的な場所は章をまたいでも表記を統一するよう指示しているため、背景画像アセットを使い回しやすい。
  世界設定に地名が登録されている場合は、それを優先して使うよう指示している。
- **`■場面:`**：時間帯や状況を含めた、内容から推測される場面の呼び名（例：深夜の岸壁）。
  表示・参考用の情報で、背景画像の判別には使わない。

この2行は、章の新規生成・再生成だけでなく、「本文のAIによる部分修正」でも維持・更新されるよう
指示している（修正によって場所や時間帯が変わった場合は、この2行も合わせて書き換えさせる）。

1つの章の中で場面（場所や時間帯）が転換する場合は、その都度、切り替わった直後の文章ブロックの
先頭にも同じ形式で■背景:・■場面:の2行を挿入するよう指示している。そのため、1章の中に複数の
場所が登場する構成でも、`^■背景:(.+)$`のような正規表現で章内の全ての場面転換箇所を機械的に
検出できる。

## AIキャラクター/世界設定/伏線生成機能の使い方

1. 各管理画面（キャラクター管理・世界設定管理・伏線管理）の「AIでたたき台を生成」ボタンから生成画面へ
2. 生成する件数（1〜10件）・利用するAI・追加指示（任意）を入力して生成
3. プレビュー画面で候補が表示される（この時点ではまだDBに保存されていない）
4. 登録したいものだけチェックを入れて「登録する」を押すと保存される
5. 登録後は通常の編集画面から個別に内容を調整できる

章生成とは異なり、生成結果を確認してから選んで保存する一段階を挟んでいる点が特徴。
不要な候補はチェックを外すか、そのままプレビュー画面を離れれば破棄される（DBには一切残らない）。

伏線生成のみ、AIが提案した配置章・回収章の「章番号」を既存の章と照合し、
一致する章があれば自動的に紐付ける。該当する章がない場合（まだ章を登録していない、
AIが存在しない章番号を答えた等）は未設定のまま登録されるので、必要に応じて後から編集する。

## おまかせ生成モードの使い方

漫画雑誌の編集担当のように、大まかな要望だけをAI作家に伝えてすべて任せたい場合の使い方。

1. 作品詳細画面の「AIで全体プロットを生成」ボタンから生成画面へ
2. 章数（1〜20章）・利用するAI・作品への大まかな要望（任意）を入力して生成
3. プレビュー画面に、キャラクター・世界設定・全章の設計図（タイトル・要約・目的のみ、本文はまだなし）・
   伏線がまとめて表示される（この時点ではまだDBに保存されていない）
4. 登録したいものだけチェックを入れて「登録する」を押すと保存される
5. 章一覧画面に、本文がまだ空の章がずらっと並ぶので、確認しながら1章ずつ「AIで次章生成」または
   「再生成」ボタンで本文を執筆していく

本文生成時（手順5）は、その章のためにあらかじめ登録された要約・目的、および今後の章の予定が
自動的にプロンプトへ組み込まれるため、行き当たりばったりの生成にならず、全体プロットに沿った
一貫性のある本文が書かれる。この一括生成は章数が多いとAPI呼び出しが多く時間がかかるため、
本文の一括自動生成はあえて行わず、章単位で確認しながら進める設計にしている。

## 禁止事項・既知の事実欄の使い方

ミステリー作品などで「特定の展開を悟らせたくない」「時系列上の矛盾を防ぎたい」場合に使う機能。

1. 作品情報の編集画面（`projects.edit`）に「禁止事項・既知の事実」欄がある
2. ここに書いた内容は、章の本文生成・全体プロット生成・キャラクター生成・世界設定生成・伏線生成の
   **すべてのAI呼び出しで毎回自動的にプロンプトへ差し込まれる**
3. 例：
   - 「主人公が真犯人であることは最終章まで読者に悟らせないこと」（書いてほしくない方向性の抑制）
   - 「被害者Aの死亡推定時刻は22時。主人公はその時刻は駅前の喫茶店にいたことにする」（動かせない事実の固定）

一度書けば以後の生成すべてに効くので、章を生成するたびに同じ注意書きを追加指示欄に手打ちする必要がなくなる。
ただしAIによる生成である以上、完全に矛盾がゼロになる保証はないため、生成後は本文を確認する運用が引き続き重要。

## 本文のAIによる部分修正

一度生成した本文の一部だけを直したい場合（「被害者を別のキャラにしたい」「会うのを前日に変更したい」など）に使う機能。
「再生成」がゼロから本文を書き直すのに対し、こちらは**既存の本文をAIに読ませた上で、指示した変更点だけを反映**させる。

1. 章一覧の「AIで部分修正」ボタン（本文が生成済みの章にのみ表示される）から修正画面へ
2. 修正指示（例：「被害者を〇〇から△△に変更してください」）と利用するAIを入力して「修正する」
3. 修正前・修正後を見比べられるプレビュー画面が表示される（この時点ではまだファイルは上書きされていない）
4. 修正後の本文はプレビュー画面でそのまま編集もできる。内容を確認して「この内容で保存する」を押すと、
   Markdownファイルが上書きされる

**注意**：修正対象の章より後の章がすでに生成済みの場合、その章が旧設定を前提にした記述を含んでいると、
この修正によって新たな矛盾が生まれる可能性がある。後続の章がある場合は、あわせて見直すことを推奨する
（これは自動検知できないため、運用上の注意点として留意する）。

### 改行コードの正規化

ブラウザは`<textarea>`の内容を送信する際、内部の改行(`\n`)をすべて`\r\n`（CRLF）に変換して送信する。
これを正規化せずに保存すると、本文編集・AI生成・部分修正の保存を繰り返すたびに`\r`が本文に蓄積し、
表示環境によっては余分な改行に見えてしまう。これを防ぐため、`app/routes/chapters.py`の
`_normalize_newlines()`が、Markdownファイルへの書き込み・読み込みのすべての箇所で
改行コードを`\n`に統一している。

## その他の細かい機能

- **章一覧・伏線一覧の「すべて削除」**：全体プロットを再生成する前に、既存の章・伏線をまとめて削除できる。
  章を削除すると、その章を参照している伏線の配置章・回収章は自動的に「未設定」に戻る（データの不整合を防ぐため）。
  キャラクター・世界設定・作品情報はそのまま残るので、「キャラや世界観は気に入っているが、章と伏線だけ作り直したい」
  という場合は、この一括削除→全体プロット再生成（キャラクター・世界設定のチェックは外す）という流れで対応できる。
- **AI生成中インジケーター**：章・キャラクター・世界設定・伏線・全体プロットの各生成ボタンを押すと、
  生成が完了するまで画面全体にローディング表示が出る（二重送信の防止も兼ねる）。
